# Auditra

نرم‌افزار حرفه‌ای و پیشرفته‌ی ممیزی و مدیریت آب در صنایع ایران.

Auditra یک **موتور دانش مهندسی آب** است، نه فقط فهرستی از راهکارهای صرفه‌جویی: با دریافت داده‌ی واقعی یک کارخانه، وضعیت آن را محاسبه و ارزیابی می‌کند و فرصت‌های بهبود را شناسایی می‌کند. هسته مشترک همه‌ی صنایع است و هر صنعت ماژول‌ها و مدل‌های محاسباتی اختصاصی خودش را دارد.

اصول بنیادین پروژه در [`docs/PRINCIPLES.md`](docs/PRINCIPLES.md) آمده است.

## وضعیت فعلی: بسته‌ی اجرایی اول

پیش از توسعه‌ی نرم‌افزار، ابتدا بانک‌های دانش مهندسی ساخته می‌شود. بسته‌ی اول **بانک تجهیزات و سیستم‌های مصرف‌کننده‌ی آب** است.

| مورد | وضعیت |
|---|---|
| هدف اولیه | حداقل ۱۵۰ نوع تجهیز و سیستم |
| رکوردهای فعلی | ۱۷۵ رکورد در ۱۲ سیستم (SYS-01 تا SYS-12) |
| وضعیت همه‌ی رکوردها | `draft`، یعنی پیش‌نویس و منتظر بازبینی کارشناس |
| اعتبارسنجی خودکار | بدون خطا |

گزارش پوشش: [`docs/equipment_coverage.md`](docs/equipment_coverage.md)

**نکته‌ی مهم درباره‌ی منبع:** رکوردها از فایل روش‌شناسی پروژه (Methodology) و دانش مهندسی عمومی تدوین شده‌اند. فقط رکوردهایی که به بخشی از آن فایل استناد دارند فیلد `ref` دارند. استانداردهای نام‌برده‌شده در آن فایل (ISO 46001 و مانند آن) هنوز توسط انسان باز و تأیید نشده‌اند و در هیچ رکوردی استناد نشده‌اند. هیچ رکوردی قبل از بازبینی کارشناس و داشتن منبع نباید `expert_reviewed` یا `approved` شود؛ اعتبارسنج این قاعده را اجرا می‌کند.

## ساختار مخزن

```
knowledge/
  vocab/        واژگان کنترل‌شده: ۱۲ سیستم، ۱۵ گروه صنعتی، ۱۵ نوع جریان آب،
                جریان‌های دیگر، نقش آبی، پارامترها، سطوح حسابداری،
                وضعیت‌های بازبینی و فهرست منابع
  equipment/    رکوردهای تجهیز، یک فایل برای هر سیستم (SYS-01 تا SYS-12)
tools/
  validate_knowledge.py   اعتبارسنج بانک دانش
docs/
  PRINCIPLES.md           اصول بنیادین و تصمیم‌های طراحی
  equipment_coverage.md   گزارش پوشش (تولید خودکار)
```

## قالب رکورد تجهیز

هر رکورد این فیلدها را دارد: شناسه (`EQP-<سیستم>-<شماره>`)، نام فارسی (`fa`) و انگلیسی (`en`)، زیردسته (`sub`)، نقش آبی (`role`)، جریان‌های ورودی و خروجی از ۱۵ نوع جریان (`in`, `out`)، جریان‌های دیگر مانند دریفت و نشتی (`flows`)، صنایع کاربردی (`ind`)، سطح حسابداری (`lvl`)، پارامترهای قابل اندازه‌گیری (`params`)، یادداشت مهندسی (`note`)، منبع (`ref`) و وضعیت بازبینی (`status`).

## اجرای اعتبارسنج

```bash
pip install -r requirements.txt
python tools/validate_knowledge.py
python tools/validate_knowledge.py --report docs/equipment_coverage.md
```

اعتبارسنج بررسی می‌کند: یکتایی شناسه و نام‌ها، معتبر بودن همه‌ی ارجاع‌ها به واژگان، پیوستگی شناسه با سیستم، اینکه تبخیر فقط خروجی باشد، اینکه تجهیز تصفیه ورودی و خروجی داشته باشد، پوشش هر ۱۲ سیستم و هر ۱۵ نوع جریان، و حداقل تعداد رکورد.

## گام‌های بعدی

بانک‌های بعدی طبق ترتیب فایل روش‌شناسی ساخته می‌شوند. پیوند هر تجهیز به پارامترهای اندازه‌گیری، فرمول‌ها، شاخص‌ها و راهکارها در بسته‌های بعدی انجام می‌شود.
